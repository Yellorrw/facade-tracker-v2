# Фасады — учёт выполнения фасадных работ

Кистью отмечается выполненное прямо на фасадах из чертежа «Архитектурных решений»: панели облицовки, окна (противопожарная отсечка), откосы и отливы. По каждому виду работ свой слой. Объёмы по осям считаются сами. Объектов может быть несколько. Каждый пользователь видит только те объекты, к которым ему дан доступ.

## Как устроено

| Что | Где |
|---|---|
| Сервер (только стандартный Python 3.9+, SQLite) | `server.py` |
| Учётные записи из Терминала | `manage.py` |
| Страницы: вход и объекты, трекер | `static/home.*`, `static/tracker.html`, `static/app.js` |
| Объект: название, корпуса | `projects/<код>/project.json` |
| Геометрия объекта (только сжатая) | `projects/<код>/data/` |
| База: пользователи, сессии, закраска | `data/tracker.db` (в репозиторий не попадает) |

## Безопасность

- **Доступ только после входа.** Без входа сайт показывает только форму входа. Геометрия, закраска и объёмы отдаются вошедшему пользователю и только по объектам, к которым у него есть доступ.
- **Пароли не хранятся в открытом виде.** В базе только хеш PBKDF2-SHA256 (310 000 итераций) с солью. Сессия хранится в cookie `HttpOnly`, `SameSite=Lax`, а за HTTPS ещё и `Secure`. В базе лежит только хеш токена сессии.
- **Защита от подбора пароля.** Не больше 6 неудачных входов на один логин и 20 с одного адреса за 15 минут. Время ответа не выдаёт, существует ли логин.
- **Запросы только со страниц самого сайта.** Изменения принимаются только с ними: нужен свой заголовок, и проверяется `Origin`.
- **Строгая политика содержимого (CSP).** На страницах нет встроенных скриптов. Данные пользователей выводятся только как текст. Сайт нельзя встроить в чужую страницу.
- **Сервер не выдаёт лишнего.** Нет версии в заголовках, текстов ошибок и листинга папок. Наружу отдаются только файлы из `static/`.
- **Роли.** Администратор видит все объекты и управляет пользователями. На объекте пользователь может быть **редактором** (отмечает выполненное) или **наблюдателем** (только смотрит). Права проверяются на сервере, а не только в интерфейсе.

Код открыт, и это не ослабляет защиту: секретов в репозитории нет. Пароли, сессии и закраска лежат только в базе на маке.

## Учётные записи

```
python3 ~/facade-tracker-v2/manage.py add-admin ЛОГИН   # первый администратор
python3 ~/facade-tracker-v2/manage.py passwd ЛОГИН      # забыли пароль
python3 ~/facade-tracker-v2/manage.py list              # кто есть и куда у него доступ
```

Остальных пользователей администратор добавляет на сайте, на главной странице в разделе «Пользователи». Там же выдаются доступы к объектам.

## Обновление

Обновление делается в GitHub Desktop: **Fetch origin**, затем **Pull origin**.
- Сайт обновляется сразу.
- Если изменился `server.py`, сервер перезапускается сам через несколько секунд.
- База в `data/` при обновлении не трогается.

## Новый объект

1. Создайте папку `projects/<код>/` (латиница, например `v16`).
2. Положите в неё `project.json` по образцу `projects/v14/project.json` и папку `data/` с геометрией корпусов.
3. Объект появится у администратора. Остальным выдайте доступ на главной странице.

## Как считаются объёмы

- **Кронштейны, утеплитель, направляющие.** Проект — по расчёту исполнительных схем (13.10.26). Выполнено считается как проект × доля закрашенной площади фасада.
- **Противопожарная отсечка.** Считается по проёмам СПК из АР, тремя слоями:
  - примыкание — по 4 сторонам окна;
  - короб — П-образный: верх и две боковины;
  - нащельники — по двум боковинам.

  Для окна 2×2 м это 8 + 6 + 4 = 18 п.м. Внизу таблицы показан итог по отсечке.
- **Откосы и отливы.** Длины элементов по маркам АР: «О-…» — откосы, «ОТ-…» — отливы. Крышки парапетов сюда не входят.
- **Облицовка.** Площадь панелей по чертежу, м².
- **Виды, террасы и кровля.** Их можно закрашивать, но в таблицу по осям они не входят. Процент по ним показан отдельной строкой.
